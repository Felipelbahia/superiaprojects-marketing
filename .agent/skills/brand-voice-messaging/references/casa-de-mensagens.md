# Casa de mensagens

Passo "6b" da etapa 4 do `brand-builder`. A skill se chama *voice-messaging*, mas até aqui a saída era só **voz** (como a marca fala) e **pilares** (sobre o que fala). Faltava o **que a marca diz**: a promessa, as proposições de valor, as provas e a mensagem para cada pessoa. A casa de mensagens preenche esse buraco.

> **Voz não é mensagem.** Voz = *como* soa (traços, escalas, vocabulário). Mensagem = *o que* se afirma e por que o público acreditaria. Uma marca de voz irreverente e uma sisuda podem ter a mesma promessa.

**Origem (E5, 2026-10-20; direito de uso confirmado pelo usuário):** hierarquia de mensagem do `brand-strategy-framework` (arquivado em `_arquivo/mescladas/e5-brand/brand-essence/`); mensagem por estágio do funil e quadro de provas de `brand-guidelines` (arquivado em `_arquivo/mescladas/e5-brand/brand-essence/`); roteiro de marca em 7 partes de `copy-metodos-classicos/references/storytelling-storybrand.md` (StoryBrand, Donald Miller); teste de aderência de `copy-metodos-classicos/references/made-to-stick.md` (Chip e Dan Heath). Tudo `[externo]`; a aplicação é `[derivado]`.

## Antes de começar
1. `01-essencia.md`, `02-posicionamento.md`, `personas.md` aprovados (ou lacunas declaradas). Se a voz (`brand-voice.md`) já existe, a casa de mensagens a respeita; se contradiz, volta à etapa 4.
2. Ler o "O que NÃO comunicar": a casa de mensagens não pode afirmar nada que esteja lá.
3. Ler `../../brand-builder/question-formats.md`.

## Os quatro níveis (hierarquia de mensagem)

```
Nível 1  Promessa da marca (1 frase): o que prometemos entregar
Nível 2  Proposições de valor (3 a 5): os principais benefícios
Nível 3  Provas (por proposição): evidências, dados, casos, demonstrações
Nível 4  Mensagem por pessoa: o mesmo conteúdo, adaptado a cada persona
```

| Nível | Como preencher | Fonte do conteúdo |
|---|---|---|
| **1 Promessa** | Uma frase. Molde: "[Marca] é a [categoria] que [benefício único], porque [razão para acreditar]" | `02-posicionamento.md` (frase aprovada) |
| **2 Proposições** | 3 a 5, cada uma é um **resultado para o cliente**, não um recurso. Cada uma liga a uma dor aprovada de `personas.md` | Dores das personas x diferencial |
| **3 Provas** | Para cada proposição: dado próprio, caso real, demonstração, credencial, acesso. **Prova sem origem não entra**; sem prova, a proposição é marcada como promessa | Usuário (`[usuário]`) ou fontes verificadas (`[externo]`); nunca inventada |
| **4 Por persona** | Para cada persona: mensagem principal, mensagem de apoio, prova que mais pesa para ela, objeção a tratar | `personas.md` (dor, objeção, vocabulário, estágio de consciência) |

### Mensagem por estágio de consciência e de funil (opcional, profundidade longa)
Para cada persona, ajustar o foco conforme o estágio (níveis de Schwartz em `copy-metodos-classicos/references/copywriting-awareness.md`; o `roteiro-persona.md` já registra o estágio):

| Estágio | Foco da mensagem |
|---|---|
| Não sabe que tem o problema | Reconhecimento do problema |
| Sabe o problema, não conhece soluções | Educar sobre o caminho |
| Compara soluções | Diferenciação |
| Conhece a marca e hesita | Prova e redução de risco |
| Pronto para comprar | Oferta e chamada clara |
| Cliente | Realização de valor (retenção) |

## Roteiro de marca (teste em 7 partes)

Use depois do rascunho, para checar se a mensagem é uma história que o cliente entende. Fonte: StoryBrand (SB7).

| Parte | Pergunta | Regra |
|---|---|---|
| **Personagem** | Quem é o cliente e o que **uma** coisa ele quer? | O herói é o cliente, **não a marca** |
| **Problema** | Qual é o obstáculo e quem é o vilão? | O vilão é a fonte raiz do problema e o cliente o reconhece (liga ao *inimigo* da essência) |
| **Guia** | A marca mostra empatia e autoridade? | Empatia ("entendemos") + autoridade (prova) |
| **Plano** | Quais passos simples o cliente segue? | Plano de processo (tira a confusão) e plano de acordo (tira o medo) |
| **Chamada para ação** | O que fazer agora? | Direta, uma só |
| **Fracasso** | O que se perde se não agir? | Mostrar o que está em jogo, sem catastrofismo |
| **Sucesso** | Como é a vida depois? | Descrever a transformação, concreta |

Erro clássico: a marca se coloca como herói ("somos líder em..."). Se a mensagem começa pela marca, reescrever pelo cliente.

## Teste de aderência (SUCCESs)

Aplicar à promessa e a cada proposição (Heath e Heath):

| Princípio | Pergunta |
|---|---|
| **Simples** | Há uma ideia central, ou cinco? Dá para dizer em uma frase? |
| **Inesperado** | Algo quebra o padrão ou abre curiosidade? |
| **Concreto** | Dá para visualizar, ou é abstrato ("soluções", "qualidade")? |
| **Crível** | Tem prova que o público verifica sozinho? |
| **Emocional** | Conecta a algo que a pessoa sente ou à identidade dela? |
| **Histórias** | Há um caso que mostra a ideia em ação? |

Se faltar mais de dois, a proposição ainda é genérica. Regra do projeto: o texto também passa pelo `/geral-anti-slop`.

## Rodadas de perguntas (chat)
1. **Promessa.** "Se o cliente pudesse repetir uma frase sobre vocês, qual seria?" Exemplo de resposta: "Ele para de perder tempo com planilha." Mostrar a frase de posicionamento aprovada e perguntar se a promessa é essa.
2. **Proposições.** "Que 3 a 5 resultados o cliente ganha?" (ABCDE com opções derivadas das dores). Exemplo: "A. Economiza tempo  B. Reduz erro  C. Fecha mais vendas  D. Menos estresse  E. Outro."
3. **Provas.** "Para cada resultado, que prova você tem?" (dado, caso, demonstração, credencial). Se não tem, anotar "promessa a validar".
4. **Por persona.** "Para a persona 1, qual dessas proposições pesa mais e qual objeção precisa ser respondida?"
5. **Limites.** "Alguma afirmação que o jurídico ou o mercado não deixa fazer?" Vai para "O que NÃO comunicar".

## Saída: `mensagens.md` (raiz da marca)

```
# Mensagens - <Marca>
Estado: rascunho | aprovado em AAAA-MM-DD
## Promessa da marca
## Proposições de valor (3 a 5): resultado / dor atendida / prova / estado da prova
## Provas disponíveis e provas a conseguir
## Mensagem por persona: principal / apoio / prova / objeção
## Roteiro de marca (7 partes, resumo)
## Limites (liga ao "O que NÃO comunicar")
## Lacunas
```

O nome do arquivo (`mensagens.md`) é proposta; o `catalog.md` o registra como saída opcional da etapa 4.

## Erros comuns
| Erro | Correção |
|---|---|
| Proposição que é recurso ("tem relatório") | Reescrever como resultado ("sabe quanto ganhou sem montar planilha") |
| Prova inventada para parecer completa | Marcar "promessa a validar"; nunca fabricar número, caso ou depoimento |
| Marca como herói | Reescrever pelo cliente |
| Mensagem igual para todas as personas | Cada persona exige objeção e prova própria; se não, fundir personas |
| Confundir com a voz | Voz é *como*; aqui é *o que* |
